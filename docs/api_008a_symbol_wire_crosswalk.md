# API-008A symbol and wire-field crosswalk

This crosswalk records the decision made against the post-alpha baseline. It
is intentionally an inventory of the current surfaces, not a provider-port
plan. The canonical new-consumer import is:

```python
from exhaust_plume.api import v1 as plume_api

request = plume_api.VisualSectionedTubeRequest(
    output_frame_id='world',
    sampling=plume_api.VisualSampling(maximum_section_count=32),
)
```

## Namespace disposition

| Namespace | Public symbols | Disposition |
| --- | --- | --- |
| `exhaust_plume.api.v1` | v1 request/result models, metadata, capabilities, errors, schema registry, and the canonical `ProductProvider` → `ProductSession` → `ProductSnapshot` lifecycle | Canonical public facade. Every model and lifecycle protocol listed here is an alias to the shipped `contracts` authority. |
| `exhaust_plume.api` | `Pose3`, `ResultEnvelope`, `SectionedTubePayload`, `Spectral*Payload`, `PlumeApiError`, `PrescribedSectionedTubeProvider`, and the current Pascal-case lifecycle | Retain for 0.1.x compatibility. It is the pre-008A review-witness surface; new wire fields must not be added here. |
| `exhaust_plume.contracts` | `ApiModel`, common metadata, v1 visual/signature/ray models, capability specs, error types, lifecycle protocols, and schema generator | Retain as the v1 wire and schema authority. New consumers import the same objects through `api.v1`. |
| `exhaust_plume.products` | `_base` DTOs, product wrappers, mesh/plot/export workflows | Retain implementation and consumer compatibility. These are not a second wire authority; provider ports will adapt them to `api.v1`. |
| `exhaust_plume.providers` | canonical product providers plus explicitly named 0.1.x compatibility providers and lifecycle symbols | New providers use the v1 product lifecycle. `providers.compatibility` owns the retained legacy imports; old spatial/static providers are not the v1 authority. |
| `exhaust_plume` | root convenience imports for physics, products, providers, and v1 contracts | Retain in 0.1.x. New documentation uses `exhaust_plume.api.v1`; root curation is deferred to API-010. |

## Wire-field mapping

| Product or envelope | Existing v1 fields (frozen) | Units and frame rule |
| --- | --- | --- |
| `ResultMetadata` | `capability`, `result_id`, `request_digest_sha256`, `snapshot`, `output_frame_id`, `claims`, `applicability`, `provenance`, `warnings` | Capability is name plus major. `output_frame_id` names the frame for all product geometry/radiometry. Digests are lowercase SHA-256 strings. |
| `SnapshotMetadata` | `snapshot_id`, `session_id`, `time_s`, `source_pose`, `dynamic_state_digest_sha256`, `ambient_state_digest_sha256`, `provider_state_digest_sha256`, `expires_at_utc` | `time_s` is seconds; pose translation is metres; quaternion order is `(x, y, z, w)`. |
| `VisualSectionedTubeRequest` | `output_frame_id`, `sampling`, `requested_channels`, `include_visual_bounds` | Section arc length, centres, radii, and bounds are SI metres; section quaternions are `(x, y, z, w)`. |
| `VisualSectionedTubeResult` | `metadata`, `sections`, `channels`, `visual_bounds`, `summary` | Geometry only. Appearance claims do not imply radiance, opacity, or optical transfer. |
| `SpectralSignatureRequest` | `direction_frame_id`, `source_to_observer_directions`, `wavelengths_m`, optional operating state | Directions are unit vectors in the named frame; wavelength is strictly increasing and in metres. |
| `SpectralSignatureResult` | `spectral_radiant_intensity`, `validity_mask`, `direction_status`, optional uncertainty | Intensity is nonnegative `W sr⁻¹ m⁻¹`; failed rows use neutral zero placeholders and an explicit status. |
| `SpectralRayTransferRequest` | `ray_frame_id`, origins, directions, `ray_t_min_m`, `ray_t_max_m`, `wavelengths_m`, quality and partial-result policy | Origins and intervals are metres; directions are unit vectors; intervals satisfy `0 <= t_min < t_max`. |
| `SpectralRayTransferResult` | `source_spectral_radiance`, `background_transmittance`, `validity_mask`, `ray_status`, `hit_mask`, optional optical depth and intersection interval | Source radiance is `W m⁻² sr⁻¹ m⁻¹`; background transmittance is `[0, 1]`; optical depth is dimensionless; miss and failed-ray placeholders are explicit. |

## Lifecycle and error mapping

The public semantic terms remain provider → session → snapshot → one product.
The v1 callable ABI is now fixed as `create_session` → `create_snapshot` →
`evaluate`, with a typed `CapabilitySpec` binding each request to one result
model. The older `snapshot`, `get_product`, `resolveCapability`, and
camelCase provider methods remain only in the compatibility modules and are
not extension points for new providers. API-009 tests both the canonical
providers and the explicit compatibility waivers.

All public failures must remain structured: v1 compatibility errors use the
typed `contracts.errors` classes, while the review-witness `PlumeApiError`
remains available for the existing prescribed provider. A provider must not
turn an unsupported capability, out-of-domain request, or invalid frame into a
plausible product with missing metadata.

## Evidence

- `exhaust_plume.api.v1` imports the exact model objects from
  `exhaust_plume.contracts`.
- `exhaust_plume.api.v1` lifecycle names are identity aliases of the
  `contracts.lifecycle_v1` protocols.
- The schema registry and generator are identity aliases, not copies.
- The canonical API tests load the checked-in visual, signature, and ray
  fixtures through `api.v1` and exercise the existing visual consumer through
  that namespace.
