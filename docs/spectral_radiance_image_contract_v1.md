# Per-pixel spectral-radiance contract v1

`plume.image.spectral-radiance@1` describes a source-bound spectral-radiance
image on an explicit pixel grid before detector response. It is a derived
supporting capability: the adapter consumes one exact ray-transfer request
and result plus an explicit ray-to-pixel geometry. It does not advertise a
plume provider or establish physical radiance validity.

## Quantity and aggregation

For pixel `(row, column)` and wavelength `lambda`, the source-only image value
is the normalized collection-weighted mean of its mapped ray samples:

```text
L_pixel(lambda) = sum_i(weight_i * L_ray_i(lambda)) / sum_i(weight_i)
```

The weights have units `m² sr`; normalization leaves the radiance unit
`W m⁻² sr⁻¹ m⁻¹`. Background transmittance is aggregated separately with the
same weights. The image does not add background radiance, detector response,
optics, exposure integration, dark current, noise, or digitization.

## Exact inputs and invalid pixels

`SpectralRadianceImageRequest` binds the pixel frame, ray frame, exact ray
request digest, exact ray-result ID and digest, complete pixel-geometry digest,
pixel dimensions, ray-to-pixel indices, and collection weights. The public
adapter rebuilds this request from the supplied objects and rejects any
mismatch. The result contract also requires adapted derivation and checks that
its request, ray request/result, and pixel-geometry digests agree with the
result fields and provenance metadata. Numeric image values and collection
weights reject booleans; validity masks accept only booleans.

A pixel is invalid when it has no mapped rays or any mapped ray is invalid.
Invalid pixels use zero source-radiance and unit-transmittance placeholders,
plus a non-OK `SampleStatus`; the result retains sample count and collection
weight so missing coverage remains visible. A valid ray miss remains a valid
zero source-radiance sample.

## Python interface

```python
from exhaust_plume.api.v1 import (
    make_spectral_radiance_image_request,
    to_spectral_radiance_image,
)

request = make_spectral_radiance_image_request(
    ray_request,
    ray_result,
    geometry=pixel_geometry,
    pixel_frame_id="sensor-pixels",
)
image = to_spectral_radiance_image(
    request,
    ray_request,
    ray_result,
    geometry=pixel_geometry,
)
```

The checked-in JSON Schema and synthetic contract fixture are generated by
`scripts/generate_public_contract_assets.py`. The fixture checks serialization
and result validation; it is not radiation or detector validation data.

## Product and release boundary

This result remains separate from `plume.fpa.detector-frame@1`. That FPA
contract carries expected electrons, masks, variance, and optional ADC counts;
it cannot stand in for per-pixel spectral radiance. The image capability's
request/result contract, deterministic adapter, and standard static and linked
interactive Visualization views are implemented. The view reports exact pixel
indices and carries source lineage; it does not turn pixel indices into angles
or physical coordinates. Provider-bound radiation qualification and
observation validation remain open, so its extension-manifest support gate
keeps `release_supported: false`. The synthetic fixture is contract software
evidence, not radiation or detector validation data.
